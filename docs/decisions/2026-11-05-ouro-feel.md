# 2026-11-05: Ouro Feel, deterministic checks of how an app feels

Status: accepted (W12 of the HX and AX native program).

## Context

Across Gatefold builds 16 to 19 and Spoonjoy's jank work, taste-review agents rewrote ad-hoc XCUITest drivers for
checks that never change, and two blockers slipped through: reviewers ran warm simulators, and the simulator accepts
XCUITest taps past the window's edge, where no finger can reach (Gatefold build 19's portrait Fine-Tune panel). Ari,
2026-11-05: "all this testing and validation should be happening as deterministically as possible. let's make it easy
for agents!!", and later: "backwards nav must always be easy! we must fix all these genres of jank".

## Decision

1. **Two products here, not a new repository.** `OuroFeel` (XCUITest driver; links into a UI test bundle) and
   `OuroFeelCore` (pure analysis, no XCTest). Every rule lives in the core and has a unit test that runs with
   `swift test` on any Mac; the driver only reads the screen and acts.
2. **Genres, app-wide.** Checks are named by the genre of jank they catch (`FeelGenre`): the way back, overlay
   dismissal, inside the window, tap landing, double-draw, jump after landing, late or lingering chrome, snap with no
   transition, settle time and place stability, plus hitches as a measure. Each has a one-line "what good feels
   like". The way back walks every screen reachable from the entry points (cells, links and buttons, up to a depth);
   it is not a single-screen check. Overlays, motion and place check what the caller names.
3. **Frames, never `isHittable`.** Layout compares accessibility frames with the window, because the simulator calls
   off-window controls hittable and taps them.
4. **Content-free place checks.** Place stability compares 16 hex digits of SHA-256; a report never holds the text.
5. **Calibrated reports.** Every `FeelResult` carries its environment (simulator, device or Mac; model; OS), how the
   run started (cold only when `scripts/ouro-feel-cold.sh` started it; otherwise "not labelled, treat as warm"), and
   the clock (the test runner's wall clock, sampling accessibility snapshots). Findings that go beyond a measurement
   are marked inference.
6. **What a film can see.** XCUITest waits for the app to go idle after a tap, so a film sees what follows a
   transition but not the frames inside a tap-driven one. Motion inside a transition is filmed by letting the app
   start it (a launch argument), as the fixture does. Mid-animation SwiftUI stretches the accessibility frame from
   the drawn position to the destination (seen on the iOS 27.2 simulator), so a sample at another size than the
   resting one counts as an in-between position. Snapshots hold the app's main thread, so films sample every 0.05 s,
   not back to back. Snap and settle fail as unjudgeable when samples are usually more than 0.15 s apart: on a busy
   Mac (load average about 760 during these runs) a bug film's samples were 0.4 to 2.7 s apart, and a check must
   never pass on what it could not see.
7. **Hitches stay a measure on the simulator.** `FeelHitches` analyses display-link timestamps from an in-app probe;
   `measureHitches` wraps `XCTHitchMetric`. Neither gates on the simulator.
8. **Proof by fixture.** `Examples/OuroFeelFixture` has one page per genre with a known bug behind `-bug 1`; its UI
   tests prove every check fails on the bug and passes without it, on the free `macos-26` runner for every pull
   request.
9. **No retries.** The runner never passes `-retry-tests-on-failure`; a tap-landing trial is one tap.

## Prior art

Checked 2026-11-05; the full table with sources is in the desk's W12 evidence (`prior-art.md`).

| Prior art | Verdict | What we take |
|---|---|---|
| [WWDC20 "Eliminate animation hitches with XCTest"](https://developer.apple.com/videos/play/wwdc2020/10077/) | adopt | Hitch ratio thresholds (under 5 ms/s good, over 10 critical) and run hygiene |
| `performAccessibilityAudit` ([WWDC23](https://developer.apple.com/videos/play/wwdc2023/10035/)) | adopt (already) | Through `ouroAccessibilityAudit`; Feel does not rebuild its hit-region or clipping checks |
| `xcrun simctl create`, `erase`, `delete` | adopt | The cold-start runner's lifecycle, deleting each simulator |
| `XCTOSSignpostMetric` navigation and scroll metrics (XCTest `XCTMetric.h`) | borrow | Duration only; the simulator reports no hitch figures |
| `XCTApplicationLaunchMetric(waitUntilResponsive:)` | borrow | Its definition of launch, for later launch timing in the runner |
| `XCTHitchMetric(application:)`, iOS 26 (XCTest `XCTMetric+UIAutomation.h`) | watch | Wrapped as `measureHitches`; recorded once on the simulator before trusting it |
| [Android Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-metrics) and [JankStats](https://developer.android.com/topic/performance/jankstats) | borrow | Cold, warm and hot labels on every result; the "twice the refresh interval" jank rule |
| [Google Accessibility Test Framework](https://github.com/google/Accessibility-Test-Framework-for-Android) | borrow | Touch-target and duplicate-bounds ideas, for v0.2 |
| [Flutter `traceAction`](https://docs.flutter.dev/cookbook/testing/integration/profiling) | borrow | A summary JSON per action beside the raw samples |
| [EarlGrey 2](https://github.com/google/EarlGrey/tree/earlgrey2) | borrow | Its stricter visibility idea; the real tap remains the proof that a covered control works |
| [Maestro `waitForAnimationToEnd`](https://docs.maestro.dev/api-reference/commands/waitforanimationtoend) | borrow (inverted) | Wait for still samples, but never settling is a finding, not a pass |
| `xcodebuild -test-iterations`, `-retry-tests-on-failure` | borrow, ignore | Iterations for warm loops; never retries |
| [Emerge Tools (Sentry)](https://docs.emergetools.com/docs/performance-testing), [SnapshotPreviews](https://github.com/getsentry/SnapshotPreviews) | watch | Build A/B comparison, previews as snapshots |
| [swift-snapshot-testing](https://github.com/pointfreeco/swift-snapshot-testing) | ignore | `OuroSnapshot` covers pixels; Feel hashes text |
| [KIF](https://github.com/kif-framework/KIF) | ignore | Runs inside the app; Feel stays a black box |

## Consequences

- Apps link `OuroFeel` into their UI test bundles; no app code changes except launch arguments for filmed
  transitions and an optional hitch probe.
- v0.2 candidates: the way-back walk's gestures on iPad, filmed transitions from host video, overlay discovery,
  launch timing, overlapping or small targets, device hitch gating, a scroll-axis signal from scroll bars,, a walk time
  budget, and a fixture text field whose software keyboard shows (a simulator with a hardware keyboard connected
  hides it, so the walk's keyboard rule is untested there).
