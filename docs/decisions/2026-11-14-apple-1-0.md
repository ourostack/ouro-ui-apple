# 2026-11-14: What Ouro HX for Apple needs for 1.0

Status: accepted. 1.0 is tagged only when every criterion below holds; until then releases stay 0.x minors and
patches.

## Context

Seven of the eight models in the 2026-11-14 model review marked Ouro UI down for the Apple half: "the Apple half is
0.5.0 pre-1.0 with five SwiftUI components" (Opus 5), "its component set is limited" (Terra), "a narrower component
set" (Astra) ([ouro-ui's model reviews](https://ui.ouroboros.bot/docs/model-reviews/),
`scripts/model-reviews/results/2026-11-14-rerun--*` in ourostack/ouro-ui). Web has 101 component folders
(`registry/ouro/components/ouro/` at ourostack/ouro-ui `main`); this package has five.

What our own apps need matters more than web's count. So the component list below comes from a census of what
Spoonjoy, Ouro MD and Gatefold hand-roll today.

## The census: what our apps hand-roll

Method: every `struct … : View` and every `ButtonStyle`, `ViewModifier`, `ToggleStyle`, `ProgressViewStyle` or
`Shape` outside tests, at each app's `origin/main`:

```sh
git grep -nP "struct \w+(<[^>]*>)?\s*:\s*(some )?[\w, ]*\bView\b" origin/main -- '*.swift' ':!*Tests/*' ':!*UITests*'
git grep -nP "struct \w+\s*:\s*[\w, ]*(ButtonStyle|ViewModifier|LabelStyle|ToggleStyle|TextFieldStyle|ProgressViewStyle|Shape)\b" origin/main -- '*.swift' ':!*Tests/*'
```

Each hit was then sorted by hand into a job a kit should own (a row, a badge, a text field) or the app's own domain
(a cookbook shelf, a page curl, a Live Activity). The job for every view is in
[`2026-11-14-apple-1-0-census.tsv`](2026-11-14-apple-1-0-census.tsv); the domain views are not listed.

Two findings shape the plan:

1. **No app uses any of the five components.** 30 of the 109 hand-rolled views do a job a shipped component
   already does (empty states, buttons, banners). Breadth alone won't fix that; adoption is a 1.0 criterion too.
2. **This package hand-rolls them as well.** `OuroA2UI` draws A2UI's `Card`, `Badge`, `DescriptionList` and
   `Separator` with private views (`Sources/OuroA2UI/A2UISurface.swift`), so an agent's card and an app's card can
   drift apart. Each of these becomes a public component that `A2UISurface` uses.

## Decision

### 1. The component set for 1.0

Eighteen components: the five there are now, and thirteen new ones, each named as on web (AGENTS.md, "Names match
web"). The order is by leverage: how many hand-rolled views a component replaces, raised where `OuroA2UI` already
needs it or where another component builds on it.

| # | Component | Replaces | Why this place |
|---|---|---|---|
| 1 | `OuroBadge` | 6 | A2UI's `Badge` draws a private one today; rows and cards put badges in their trailing slot |
| 2 | `OuroCard` | 7 | A2UI's `Card` draws a private one today; it is the surface rows and figures sit on |
| 3 | `OuroItem` and `OuroItemGroup` | 17 | The most hand-rolled job in all three apps |
| 4 | `OuroTextField` | 9 | Every editor and sign-in screen |
| 5 | `OuroAvatar` | 8 | Leading media for rows; Spoonjoy's chefs and profile |
| 6 | `OuroPageHeader` | 7 | Spoonjoy's section headers and masthead |
| 7 | `OuroSkeleton` and `OuroSpinner` | (in the 13 states) | The loading half of the states `OuroEmptyState` doesn't cover |
| 8 | `OuroProgress` | 6 | Cook progress, update download |
| 9 | `OuroSegmentedControl` | 5 | Gatefold's reader settings, Spoonjoy's cook steps |
| 10 | `OuroCheckbox` | 4 | Ingredient and step checklists |
| 11 | `OuroDescriptionList` | 3 | A2UI's `DescriptionList` draws a private one today |
| 12 | `OuroSyncStatus` | (in the 8 banners) | Gatefold's and Spoonjoy's offline and sync lines |
| 13 | `OuroSeparator` | 1 | A2UI's `Separator` draws a private one today |

Not in 1.0: command palette, toolbar and dock, slider and number field, timer, share. Each is used by one app; it
joins after 1.0 when a second app needs it, or when that app's team brings it.

### 2. The measurable 1.0 criteria

1.0 is tagged when all of these hold at the release commit:

- **Components.** All eighteen above are public in `OuroHX`. Each has a palette value and `ContrastTests` in every
  theme, light and dark, standard and increased contrast. Each has snapshot references for both CI macOS majors
  (`__Snapshots__/macOS-26`, `macOS-27`) and a gallery page that passes `ouroAccessibilityAudit` at the default text
  size and at accessibility XXXL. Each has a DocC article that names its web twin and credits the app it came from.
- **Claims.** Core's `components.claims.json` lists every one of the eighteen in `appliesTo` for each claim that
  applies to it, with an `apple` check naming the Swift test. `ClaimCoverageTests` passes, and the release's iOS 27
  claims run passes (RELEASING.md step 2) with the log attached. `A2UISurface` draws every catalog component with
  the public component of the same name; no private view stands in for one.
- **Platforms.** iPhone, iPad and Mac. The gallery's UI tests run on an iPhone and an iPad simulator, and the
  snapshots on macOS. The iPhone Duo fold postures are covered for the components that change with them (sheet,
  item, card). The floor stays iOS 18 and macOS 15.
- **API stability.**
  - README gains a source-stability section. Its model is
    [swift-argument-parser's](https://github.com/apple/swift-argument-parser#project-status): the public API is the
    non-underscored public declarations of the library products, and a source break waits for 2.0.
  - From 0.9.0, CI runs
    [`swift package diagnose-api-breaking-changes`](https://github.com/swiftlang/swift-package-manager/blob/main/Sources/PackageManagerDocs/Documentation.docc/Package/PackageDiagnoseAPIBreakingChange.md)
    against the previous tag. A pull request that breaks the API says so in its title.
  - The two minor releases before 1.0 make no source break.
- **Adoption.** Spoonjoy, Ouro MD and Gatefold each use `OuroButton`, `OuroEmptyState`, `OuroBanner` and `OuroItem`
  in at least one shipped screen. The census above is rerun, and its kit-shaped count, now 109, is recorded in the
  1.0 release notes. Changes to the apps go through their own repositories' process (AGENTS.md); this package never
  edits them.

### 3. How each component ships

Each component is its own small pull request, released as a minor:

1. A core pull request adds the component to `appliesTo`, with its `apple` check.
2. This package's pull request adds the component, its tests and snapshots, and its gallery page.
3. `OuroA2UI` switches to the component, where the catalog has one.
4. A minor release, through RELEASING.md.

A component may ship before core's release that lists it. Its claims are then proven here first, and the
pull request says so. The claim's `apple` check is added to core in a follow-up.

## Prior art

Checked 2026-11-14.

| Prior art | Verdict | What we take |
|---|---|---|
| [swift-argument-parser, "Project Status"](https://github.com/apple/swift-argument-parser#project-status) | adopt | The source-stability statement: what counts as public API, and that a source break waits for a major version; a new toolchain requirement is a minor |
| [SwiftPM `diagnose-api-breaking-changes`](https://github.com/swiftlang/swift-package-manager/blob/main/Sources/PackageManagerDocs/Documentation.docc/Package/PackageDiagnoseAPIBreakingChange.md) | adopt | The API stability gate, against the previous tag (present in Swift 6.x: `swift package diagnose-api-breaking-changes --help`) |
| [Fluent UI Apple](https://github.com/microsoft/fluentui-apple) | borrow (lesson) | Microsoft's design system for iOS and macOS is still 0.x ([0.37.0, 2026-08-07](https://github.com/microsoft/fluentui-apple/releases/latest)), so a component count alone doesn't make a 1.0. Our criteria add claims, stability and adoption |
| [Material Components for iOS](https://github.com/material-components/material-components-ios) | ignore (lesson) | Archived, last release v124.2.0 (2021-04-26). It reached a high major through many breaking releases and has no source-stability promise. We avoid that |
| [Apple HIG, Components](https://developer.apple.com/design/human-interface-guidelines/components) | adopt | The checklist for which system controls a component wraps, rather than redraws (text fields, toggles, segmented controls, progress) |
| [A2UI](https://github.com/google/A2UI) | borrow | Its catalog-first shape. Core's HX catalog (`standard/hx/a2ui/catalog.json`: Card, Stack, Heading, Text, Image, Badge, List, DescriptionList, Separator, Alert) sets the first components, so an agent's surface and an app's screen share components |
| [swift-snapshot-testing](https://github.com/pointfreeco/swift-snapshot-testing) | ignore | `OuroSnapshot` already keeps per-macOS references, as `2026-11-04-hx-components.md` records |

## Consequences

- The README's component list grows with each release, and so do ui.ouroboros.bot's Apple pages and parity tables.
  ouro-ui is making its Platforms pages generate from release data. Until that lands, its `Apple release` check
  opens its "Apple pages are behind" issue after each release here (`scripts/apple-release.mjs` in ourostack/ouro-ui).
- The census is a hand sort. The next one reruns the two commands above and sorts only the views that are new
  since this one.
